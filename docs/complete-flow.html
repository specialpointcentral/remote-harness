一眼区分两种模式

判断标准只有一个：Codex 在哪里运行，项目和工具链在哪里运行。

Simple Reverse

远程开发本地项目

Codex 在远端盒子；项目在笔记本；Bash 由会话 hook 自动路由回笔记本。

远端盒子Codex TUI
远端挂载点
笔记本项目目录
真实工具链

sshfs 把笔记本项目挂到远端；构建、测试、运行通过反向隧道回笔记本执行。

Simple Forward

本地开发远程项目

Codex 在本机；项目在服务器；命令经 `ssh <server-alias>` 到服务器。

本机Codex TUI
本地挂载点
SSH 服务器项目目录
真实工具链

sshfs 把服务器项目挂到本地；构建、测试、运行通过 SSH 回服务器执行。

共同入口

无论 reverse、forward 还是不确定模式，公开入口都是 `simple-bootstrap.sh`。

用户启动 skill例如 `$remote-harness 中文，yolo`。Skill 只判断模式、语言、运行时和是否显式 YOLO。
返回本地命令命令必须在用户本地终端运行。具体 SSH target、路径和挂载点不进入聊天上下文。
Bootstrap 准备脚本本地安装时直接执行；远端 source 时抓取 helper bundle 到 `~/.remote-harness/.sessions/bootstrap.*`。
Dispatcher 选择模式有 `--mode` 就直接进入；无 `--mode` 则本地交互选择，默认 reverse，并缓存选择。

脚本来源机器不等于项目机器。Forward 中 source 只用于读取 remote-harness 脚本，项目服务器仍由本地 forward 向导单独询问。

Codex 看到什么

两种模式都把 SSH config 隐藏在会话 runner 后面，让 Codex 运行普通相对命令。

Reverse 路由

文件像在远端，命令回笔记本

npm test cargo build

Codex 工作目录是远端挂载点；hook 自动映射 cwd 并在笔记本执行 Bash。

Forward 路由

文件像在本地，命令回服务器

npm test pytest

Codex 工作目录是本地挂载点；hook 自动映射 cwd 并在服务器执行 Bash。

场景 Codex 工作目录 文件读写 Bash 命令 Codex 参数
Reverse 远端挂载点 写回笔记本项目 hook 自动路由到笔记本 instructions + `hooks.PreToolUse`
Forward 本地挂载点 写回服务器项目 hook 自动路由到服务器 instructions + `hooks.PreToolUse`
非 YOLO 同上 同上 允许 runner 使用 SSH 网络 `-s workspace-write` 和必要 writable roots
YOLO 同上 同上 同上 `--dangerously-bypass-approvals-and-sandbox`

文件、缓存与清理矩阵

原则是：SSH runtime 进入 `~/.remote-harness/.sessions`；用户选择的项目/挂载点按用户意愿使用。

缓存

本地默认值

`simple-cache.env`、`simple-forward-cache.env`、`simple-mode-cache.env` 只保存在本机，用于下次提示默认值。

临时会话

SSH runtime

`known_hosts`、session ssh_config、rule、wrapper 都在 `~/.remote-harness/.sessions`，会话 SSH config 关闭 multiplexing。

持久复用

远端 reverse key

远端 `~/.remote-harness/keys/id_ed25519` 是 remote-harness 专用 identity，不放进远端 `~/.ssh`。

退出时 Reverse Forward
卸载 远端卸载 sshfs 本机卸载 sshfs
规则 删除远端 session rule 删除本地 session rule
SSH config 删除本地和远端临时 config 删除本地临时 config
认证 引用计数为 0 时删除 `authorized_keys` 托管块 不写本机 `authorized_keys`
隧道 没有其他挂载使用时关闭 `ssh -N` 无反向隧道

长期稳定性提醒

会话级配置让单次连接更稳；共享服务器还需要服务端容量配合。

Server tuning

多用户与长期 SSHFS 挂载

remote-harness 会使用临时 SSH config、临时 known_hosts、sshfs reconnect 和 keepalive。 如果一台远端开发服务器承载多个用户或大量长期挂载，还应检查 sshd 的 MaxStartups、MaxSessions、 ClientAlive，systemd/PAM nofile 和 TCP 队列。 详见 ssh-sshfs-long-lived-connections.cn.md。

最终心智模型

记住这两句话，基本就不会把方向搞混。

Reverse

远端 Codex，命令回笔记本

远端盒子承载 Codex 和挂载目录；真实项目和工具链在笔记本，Bash 由 hook 自动路由回去。

Forward

本地 Codex，命令回服务器

本机承载 Codex 和挂载目录；真实项目和工具链在服务器，Bash 由 hook 自动路由回去。
